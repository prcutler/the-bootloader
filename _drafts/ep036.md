Where to start with this one? First, Let me start this by saying I'm not a game designer - I don't know anything about designing games, so if I get some of the details wrong here, I'll just apologize up front. One of the knocks against CircuitPython is that it's not fast when compared to Arduino or C, and that's ok, that wasn't a primary feature for CircuitPython. But that perception may be why CircuitPython doesn't have a lot of home brew games for it and that's where picogame comes in.

picogame was created by Vladimír Smitka and he's created a [great write-up of picogame on chiptron.eu](https://chiptron.eu/picogame-a-game-engine-for-circuitpython/). 

picogame is a small 2D game engine built on top of CircuitPython and requires about 200k of RAM to run, and it can run on the rp2040 and 2350 family as well as a number of boards from Espressif.

What smitka - as he goes by in Discord - has created, is a game engine written in C, compiled into CircuitPython. This handles all the graphics, including collisions and other computationally heavy tasks. On top of that is a set of Python libraries to help with USB gamespads, keyboards, audio and synthesis, animation, score saving, and more.

This lets the programmer focus on what's important - the game design. And the game programming is done in CircuitPython and we all know that Python is one of the more popular languages and CircuitPython tries to conform as much as possible with CPython, or desktop Python.

smitka then shares his motivation for creating picogame in that he had a PicoPad, a Czech-made handheld gaming device using an rp2040. 

[Scroll to picopad picture in article]

The PicoPad had a picture of a Defender like game on it and smitka tried to recreate it, but found `displayio` too slow. And so, picogame was born. With picogame using a core written in C, performance goes way up and the article also shares the impressive performance stats. There's an Adafruit game called Bouncing Balls that runs at about 115 frames per second normally.  With picogame's compatibility layer? More than double to 250 frames per second.

We mentioned Dan Cogliano's Moon Miner game earlier. smitka re-wrote it in picogame and not only was it 6x faster, the code was 40% smaller thanks to the engine's native functions.

So what can you create and how do you create a game with picogame? It has a [fantastic documentation website](https://picogame.makerclass.cz) and has demos built in and ready to play. And by ready to play, you can play right in your browser with what I'm guessing is either PyScript or web assembly, I'm not sure. 

[Scroll to Try it now, right in your browser - click on Playground]

It says it's loading MicroPython and now you're playing a block game, a Tetris-like clone. All the code is below the game, and you can see that it's running in CircuitPython in less than 200 lines of code.

There's over twenty games to choose from - from side scrollers to arcade games to logic puzzles. You can also try them out locally - after cloning the git repository, you can run them all using CPython's PyGame to run them right on your PC.

Looking at the documentation, it shares *how* it works, a high level overview of game design, and then it jumps right into the guides on creating your own game. It also has a number of pre-made snippets to help get you up and coding in no time.

And lastly, it includes a game design skill to help you build a game with an AI agent like Claude Code. 

[Click on Build with AI Agent tab]

The skill includes game design fundamentals, game examples, how the engine works, and more.  Then just give your AI a prompt like "Make a tiny shooter for picogame" and off it goes.

The development has been in the open - smitka has shared progress and asked for feedback in the #circuitpython-development Discord channel. There was even just a recent discussion about - if I understood it right - including picogame in the CircuitPython core and not as a library. I think this is an awesome idea - the batteries included nature of having this built right in to CircuitPython would make it a great fit. Pair it with something like the Fruit Jam and we'll have to get the word out to maker and home brew game communities that there's a new game platform on the block!

### Tod
Another retro-inspired project from Liz Clark I really like is her
[CircuitPython Chiptune Player](https://learn.adafruit.com/circuitpython-chiptune-player)
It puts a Feather, an I2S audio DAC, and a touchscreen display into a 
case that looks like an old coin op video game. It lets you load an SD card with 
retro chip tunes and play them. 

At first you might think this is just an MP3 or WAV player, but no! It's
so much cooler than that.  Liz made a [CircuitPython library](https://github.com/adafruit/Adafruit_CircuitPython_AY8912) that uses
synthio to emulate the AY8912 sound chip that was so many coin op video games
from the 1980s.  All those bleeps and boops you think of from old video games
are probably sounds generated from the AY8912.  Unlike today's modern game sound
generation hardware, back in the 80s, these specialized chips handled it all, 
but had specific limitations.  For the AY8912, you get three channels of sound,
each channel could play either square wave or white noise, with adjustable pitch
and volume. There was one envelope generator for the whole chip. But with that
a clever game designer could create entire video game sound tracks with 
game sound effects. Some of my favorite arcade games that used this chip
are Frogger, Tron, and Spy Hunter.

These chips are so beloved that there is a special file format called ".VGM" 
(for "video game music") for storing chip instructions and [fan websites](https://vgmrips.net/packs/chip/ay-3-8910) with archives of these VGM files. 
And it's these VGM files that Liz's AY8912 library (and thus Chiptune Player) parses and plays.  The library is a good demonstration of using synthio 
to solve a concrete audio design goal and shows that the result can be pretty 
elegant and compact.  And it's fascinating that here we are emulating hardware
chips in Python that runs on an chip.  Thanks Liz! I've been slowly working
on an SN76489 sound fx chip emulator and may steal some ideas from your library!

### Tod

The PICOTTY project helps you manage a server cluster using a collection of Picos
running CircuitPython and a Raspberry Pi 2W.
It's a niche tool for system administrators to manager groups of machines, 
but shows how useful CircuitPython can be even in these demanding environments. 
The problem with servers is they are "headless" (no screens or keyboards)
but still you need to be able to remotely type on their keyboards and see
their console messages, especially when booting. 
Normally this means buying expensive remote management hardware. 
But security researcher Chiranjeevi created a low-cost system for
networked serial console with keyboard injection using a bunch of Raspberry Pi
Picos running CircuitPython and a Raspberry Pi 2W to manage them and provide
network access. The CirPy Picos feed keystrokes to the server and receive
console messages over USB CDC. 
The Raspberry Pi 2W hub application provides a nice web interface to control
all these Picos, see the server messages, send keystrokes, even do OTA updates
of the Picos remotely. 

Note this only works for OSes where the boot messages can be redirected from the
screen to USB serial, which restricts it Linux servers, but that's most servers.

They also provide a nice small 3d printable enclosure that holds the Pi 2W and four 
Pico nodes, letting you quickly get a home lab cluster going. 

- [PICOTTY github repo](https://github.com/morpheuslord/PICOTTY/)
- [Embedded Systems News story](https://www.cnx-software.com/2026/08/06/picotty-project-enables-multi-target-serial-remote-management-through-raspberry-pi-pico-boards-and-pi-zero-2-w-sbc/)
